# Бухгалтерия YAB STUDIO

Скачки: отчёт отдельно учитывает ставки, выигрыши и возвраты. Если таблицы
скачек уже созданы, показывает общий баланс фонда, обязательства по ставкам,
свободный остаток и выделенные турнирные средства. На базе до обновления
этот блок отсутствует; локальный отчёт сам таблицы не создаёт.

## Сервер

GET /api/admin/accounting?days=30&include_admins=false доступен только пользователю с ролью admin после обычной проверки Telegram initData. Периоды: 7/30/90 дней или 0 за всё время. В профиле админа есть отдельная страница «Бухгалтерия».

Отчёт выполняется в отдельной транзакции PostgreSQL REPEATABLE READ, READ ONLY. Не запускает миграции, закрытие турниров или выдачу наград. Новых таблиц не требуется. Дни считаются по UTC+5. Текущие кошельки и сверка журнала — за всё время; движения и покупки — за выбранный период. График при «Всё время» ограничен последними 90 днями. Список кошельков ограничен 20 строками, журнал — 50 последними операциями. Количество кассет относится к покупкам за период, их возвраты могут состояться позднее.

По умолчанию исключаются аккаунты с текущей ролью admin, в том числе их обычные операции. Тестовые пополнения admin:test показаны отдельно. Это фильтр отчёта, а не отдельная тестовая валюта: реальный баланс админа остаётся в User.jera.

## Локальная страница с реальными данными

Запуск: npm run dev в frontend, затем http://127.0.0.1:5187/accounting-preview.html (если сервер поднят на порту 5187).

Vite-плагин доступен только при разработке. GET /__local/accounting принимает только соединения с loopback и локальный Host, проверяет Origin при его наличии, запрещает другие методы. Он вызывает accounting_local.py. CLI импортирует database и accounting_service, но НЕ main, поэтому приложение, бот, миграции и фоновые задачи не запускаются. Строка DATABASE_URL берётся из существующего корневого .env и не передаётся браузеру.

Машинные настройки интерпретатора находятся в .env.accounting.local, который добавлен в .gitignore. Поля: ACCOUNTING_PYTHON (полный путь к Python с зависимостями из requirements.txt), необязательный ACCOUNTING_PYTHONPATH (дополнительный каталог Python-пакетов). Локальный файл уже настроен на этом компьютере. При переносе проекта укажи собственный интерпретатор.

Отчёт не кладётся в public/static. Данные доступны локально по запросу и по защищённому серверному API после деплоя. JSON-экспорт скачивается только по кнопке пользователя. Локальный экран можно открыть до деплоя — он читает ту же существующую Neon напрямую в режиме READ ONLY.
